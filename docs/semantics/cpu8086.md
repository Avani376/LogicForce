# Semantics: 8086 Educational Core v1

Status: **CONTRACT for Phase 6** (implemented in `engines/cpu8086/cpu8086`)
Engine version: 0.6.0

## Scope decision: internal instruction representation (IR)

The assembler translates source text into a typed **internal instruction
representation**; the executor runs that IR. Native x86 machine-code
encoding/decoding (ModRM bytes, opcode maps) is **out of scope for v1** — it adds
a large binary-format surface with no educational value over the IR. This is a
documented scope decision, not a hidden simplification: the "program image" is the
assembled IR; `IP` is the **instruction index** into that image; `CALL` pushes the
return index as a 16-bit word.

## Register model

- General: `AX BX CX DX` with byte halves `AL AH BL BH CL CH DL DH`;
  index: `SI DI`; stack/base: `BP SP`; instruction: `IP`.
- Segment: `CS DS SS ES` — present and usable for address calculation.
- FLAGS (v1 subset): `CF PF AF ZF SF OF`. IF/TF/DF arrive with Phase 7
  (interrupts/string ops) and are rejected until then.

## Memory

- 1 MiB byte-addressable memory, little-endian words.
- Physical address = `(segment × 16 + offset) mod 0x100000` — **wraparound is
  defined as modulo**, matching the 8086's 20-bit address space behavior.
- Default segment per access: `BP`-based effective addresses use `SS`; everything
  else uses `DS`. `CS:IP` fetches map to `IR` lookups, not memory.
- Stack: `PUSH` writes `SP−=2; [SS:SP]=value`; `POP` reads then `SP+=2`.

## Flags — exact semantics (per Intel manual behavior)

| Op | CF | OF | ZF | SF | PF | AF |
|---|---|---|---|---|---|---|
| ADD/ADC | carry out of MSB | signed overflow | result==0 | MSB of result | parity of low 8 bits | carry bit3→bit4 |
| SUB/SUB-from/CMP | borrow | signed overflow | result==0 | MSB | parity | nibble borrow |
| INC/DEC | **unchanged** | signed overflow | result==0 | MSB | parity | nibble carry/borrow |
| NEG | 1 iff operand ≠ 0 | 1 iff operand == 0x8000/0x80 | result==0 | MSB | parity | carry bit3→bit4 |
| AND/OR/XOR/NOT/TEST | 0 | 0 | result==0 | MSB | parity | **cleared** (Intel: undefined; this implementation defines it — documented deviation) |
| MUL | upper half ≠ 0 | upper half ≠ 0 | ZF/SF/PF from the **low half**¹ | parity of low 8 bits | **cleared**¹ |
| IMUL | truncation lost² | truncation lost² | ZF/SF/PF from the low half¹ | parity of low 8 bits | **cleared**¹ |
| DIV/IDIV | unchanged³ | unchanged³ | unchanged³ | unchanged³ | unchanged³ |

¹ Intel marks ZF/SF/PF/AF **undefined** after MUL/IMUL; this engine defines them
  deterministically (same documented-deviation policy as the AND family). The low
  half is AL for byte ops, AX for word ops.
² IMUL CF/OF: 0 iff the full product fits the low half as a signed number
  (byte: −128..127, word: −32768..32767); otherwise both are 1.
³ Intel marks all flags undefined after DIV/IDIV; this engine leaves every flag
  unchanged — the cheapest deterministic choice.

- PF is the parity of the **low 8 bits** of the result: even parity ⇒ 1.
- Signed overflow (8-bit): `a` and operand share sign but result sign differs.
  Word ops use bit 15; byte ops bit 7.
- PUSH/POP/MOV/JMP/CALL/RET/LOOP/NOP/HLT modify no arithmetic flags.

## Instruction subset (v1 — authoritative)

Data movement: `MOV reg,reg|imm|mem` · `MOV mem,reg|imm`
Arithmetic: `ADD ADC SUB SBB INC DEC NEG CMP` (byte & word forms)
Multiply/divide (Phase C8): `MUL IMUL DIV IDIV r/m` — one operand; the other is
implicit. Byte: AX = AL ∗ r/m8 (MUL/IMUL); AL = quotient, AH = remainder
(DIV/IDIV, dividend AX). Word: DX:AX = AX ∗ r/m16 (MUL/IMUL); AX = quotient,
DX = remainder (DIV/IDIV, dividend DX:AX). Divide by zero or a quotient that
overflows the destination register is a typed `CpuRuntimeError` at the current
step (the real 8086 raises #DE/INT 0 — the educational engine reports the error
instead of dispatching it). IDIV truncates toward zero; the remainder takes the
dividend's sign.
Logical: `AND OR XOR NOT TEST` (byte & word)
Stack: `PUSH POP` (reg/imm/mem)
Control: `JMP label` · `JZ/JE JNZ/JNE JC/JB JNC/JAE JS JNS JO JNO JCXZ label`
· `LOOP label` · `CALL label` · `RET` · `NOP` · `HLT`
Segment: `MOV sreg, reg|imm` and `MOV reg, sreg` (data movement only)

Anything else (string ops, xlat, lahf/sahf, prefixes,
segment overrides, indirect jumps/calls) raises a typed
`UNSUPPORTED_INSTRUCTION` with the mnemonic and source line. The subset is a
**declared educational subset**, not a compatibility claim.

## Assembly syntax

- Intel-style: `MNEMONIC destination, source`. Case-insensitive mnemonics and
  register names.
- Memory: `[BX]`, `[BP+SI]`, `[BX+4]`, `[BP+SI+2]`, `[1234]` — with optional
  `BYTE`/`WORD` size prefix for ambiguous forms (`MOV BYTE [BX], 7`).
- Numbers: decimal `123`, hex `0x1A` / `1Ah`, binary `0b1010` / `1010b`.
- Labels: `name:` on their own line (or `name: MNEMONIC …`); targets resolved at
  assemble time; duplicate labels are errors; unknown labels are errors.
- Comments: `;` to end of line. Blank lines ignored.

Diagnostics are typed per the v1.0 documentation: each error carries
`line` (1-based), `category` (`SYNTAX | UNKNOWN_MNEMONIC | UNKNOWN_REGISTER |
UNKNOWN_LABEL | DUPLICATE_LABEL | BAD_OPERAND_COUNT | SIZE_MISMATCH |
UNSUPPORTED_INSTRUCTION`), and an actionable message.

## Execution and debugger semantics

- `step()`: executes exactly one instruction, then emits a trace record:
  `{step, ip, instruction, register_changes, flag_changes, memory_changes,
  halted}`. Registers report only changed values (before → after).
- `run(max_steps, breakpoints)`: steps until `HLT`, a breakpoint (checked
  *before* executing the instruction at that IP), `max_steps` exhaustion
  (bounded execution — reported as `BOUNDED(max_steps)`, never silently
  truncated), or an error (typed, with the step at which it occurred).
- `reset()`: registers to their documented power-on values (`SP = 0xFFFE`,
  others 0; memory as loaded by the program), instruction pointer to 0.
- Determinism: same source + same inputs ⇒ byte-identical trace. No clocks, no
  interrupts in v1 (Phase 7).

## Out of scope for v1 (honest list)

Machine-code encoding/decoding, segment overrides, string instructions,
interrupt handling beyond the Phase 7 model, co-simulation hooks
(Phase 8), self-modifying code semantics, per-instruction cycle timing.
